# QPyM2 v0.6: Storage Architecture & Configuration Guide

This document describes the modern data management and configuration system in QPyM2 `v0.6.0`, transitioning the framework from path-encoded directory hierarchies to an immutable, identity-addressed **Artifact Store** backed by sidecar `manifest.json` files and a structured 4-tier **Hydra Configuration** system.

---

## 1. Architectural Overview

### Problems with Legacy Path Hierarchy
Historically, analysis outputs were placed into directory trees whose paths encoded parameter strings (e.g., `model_gamma10_v150_u1740_cs0p8/`). This approach caused four major issues:
1. **Implicit path identity:** Altering an un-encoded configuration setting (such as binning or component definitions) while keeping the same folder name caused silent overwriting or stale cache hits.
2. **Duplicated upstream storage:** Downstream variations with different energy shifts or cutoffs re-materialized identical staged datasets under distinct model directories.
3. **Missing provenance:** Artifacts like `fit.h5` or `fit.nc` did not record the exact resolved parameters or upstream content IDs that produced them.
4. **HPC filesystem bottleneck:** Thousands of independent toy output folders caused inode and metadata congestion on shared networked filesystems (NERSC CFS/Scratch).

### The v0.6 Solution
The modern architecture decouples scientific derivation identity from execution metadata:
- **Identity-addressed storage:** Every product is assigned a deterministic derivation key:
  $$\text{artifact\_id} = \langle\text{kind}\rangle\_\text{sha256}(\text{operation}, \text{canonical\_params}, \text{upstream\_ids})[:16]$$
- **Immutable sidecar manifests:** Each artifact folder contains a `manifest.json` recording complete scientific parameters, file listings, upstream lineage, and execution attempt provenance.
- **Two-level prefix directory layout:** Avoids directory scaling limits by partitioning objects under `objects/<type>/<2-char-prefix>/<artifact_id>/`.
- **Atomic filesystem publication:** Workers stage artifacts into `<store_root>/.tmp/<uuid>` on the same filesystem and publish via `os.replace`, preventing race conditions across concurrent SLURM array tasks.

## 2. Configuration System (4 Tiers)

The configuration system uses Hydra and OmegaConf composed programmatically via `qpym2.cfg.hydra_adapter.HydraConfigManager`.

```
config/
├── config.yaml              # Master entry point (defaults: local, default, base, tech_note)
├── environments/            # Tier 1: System infrastructure & paths
│   ├── base.yaml            # Defaults, directory variables, output_paths.artifact_store
│   ├── local.yaml           # Local workstation data root (/data/cuore/Analysis/MC)
│   └── nersc.yaml           # NERSC Perlmutter data paths (/global/cfs/...)
├── staging/                 # Tier 2: Staging transform contract
│   └── default.yaml         # Preselection cuts & source file match patterns
├── analysis/                # Tier 3: Physics baseline & conventions
│   └── base.yaml            # Baseline background component grouping & standard cuts
└── models/                  # Tier 4: Physics models & ROI
    └── tech_note.yaml       # tech_note_200, tech_note_250, tech_note_150, tech_note_3comp
```

### Loading Configuration in Python

```python
from qpym2.cfg.hydra_adapter import HydraConfigManager
from qpym2.cfg.config_builders import (
    build_staging_config,
    build_input_config,
    get_h2uv_model,
    get_artifact_store_dir,
)

# Load configuration with environment selection
cfg = HydraConfigManager.get_config(environment="local")

# Resolve artifact store directory
store_dir = get_artifact_store_dir(cfg)

# Build stage configurations
staging_cfg = build_staging_config(cfg)
input_cfg = build_input_config(cfg, model_key="tech_note_200")
h2uv_model = get_h2uv_model(cfg, model_key="tech_note_200")
```

## 3. Storage Core Reference (`qpym2.storage`)

The `qpym2.storage` package provides the complete foundation for artifact identities, manifests, and file management.

### 3.1 Static Parameter Schemas (`schemas.py`)

All identity specifications are implemented as **frozen dataclasses**. Identity fields strictly contain only parameters that alter physical outputs; human labels (`model_key`, `name`, `dir_name`) and execution metadata (`host`, `git_commit`, `started_at`, `chains`, `draws`) are strictly excluded from derivation keys.

#### `StagingParams`
Defines parameters for staged ROOT `uvtree` files:
- `cuts`: Tuple of filter expressions (`base`, `multiplicity`, `data_quality`, `broad_preselection`).
- `source_ids`: Sorted identifiers/hashes of raw input datasets.
- `out_cols`: Output columns preserved in the tree (`u0`, `v0`, `ch1`, `ch2`, `ds`, `t`).
- `version`: Schema integer (default: 1).

#### `InputParams`
Defines parameters for fit-input histogram products (`input.h5`):
- `bin_size`: Histogram bin width in keV.
- `esum_min`, `esum_max`: Energy sum range in keV.
- `threshold`: Energy threshold for detector channels in keV.
- `histogram_type`: Default `"h2uv"`.
- `co_cut`: Optional Cobalt selection cut (e.g. `"gamma10_v150"`).
- `ndbd_cutoff`: Optional $0\nu\beta\beta$ cutoff cut (e.g. `"u1740"`).
- `skip_roi`: Optional energy range excluded from analysis (e.g. `(2500.0, 2550.0)`).
- `co_shift`, `ndbd_shift`: Applied energy shifts in keV.
- `template_transforms`: Sequence of transform specifications.

#### `FitParams`
Defines parameters for Bayesian fit problem artifacts:
- `components`: Tuple of active component names.
- `smooth`: Whether histogram smoothing is enabled (bool).
- `likelihood`: Likelihood distribution type (default: `"poisson"`).
- `priors`: Dictionary of component prior configurations.
- `co_cut`, `ndbd_cutoff`: Applied selection cuts.
- `co_shift`, `ndbd_shift`: Applied energy shifts in keV.
- `skip_roi`: Excluded ROI interval (if applicable).
- `blinded`: Blinded data flag (bool or str).

#### `ToyBatchParams`
Defines parameters for consolidated toy Monte Carlo / sensitivity batches:
- `fit_type`: Fit mode (`"toys"`, `"sens"`, or `"bias"`).
- `n`: Number of toy fits per batch.
- `co_cut`, `ndbd_cutoff`, `co_shift`: Selected model point.
- `bias_min`, `bias_max`: Signal injection range (for bias studies).
- `seed`: Batch seed offset.

#### `StudySpec`
Defines comparative studies and systematic scans:
- `name`: Study name identifier.
- `nominal`: Nominal baseline point configuration.
- `vary`: Tuple of parameter field paths varied in the study.
- `variations`: Tuple of specific variation points.
- `outputs`: Requested output products (e.g. `("fit_summary",)`).

#### `RunProfile` (Execution Metadata Only)
Recorded in the manifest, never hashed into identity keys:
- `sampler`: Sampler engine (e.g. `"pymc"`).
- `chains`: Number of MCMC chains.
- `draws`: Posterior draws per chain.
- `tune`: Tuning steps.
- `seed`: Posterior sampling random seed.
- `target_accept`: Acceptance rate target.

#### `ExecutionMetadata` (Provenance Only)
Recorded in the manifest, never hashed into identity keys:
- `execution_id`: Unique UUID for the run attempt.
- `host`: Hostname or compute node ID.
- `git_commit`, `git_dirty`: Working tree git state.
- `slurm_job_id`: SLURM job array task ID.
- `started_at`: ISO timestamp.

#### `Manifest`
Describes an immutable artifact bundle:
- `artifact_id`: Deterministic ID (`<kind>_<sha256[:16]>`).
- `artifact_type`: Storage category (`"staging"`, `"fit-input"`, `"fit"`, `"toy"`, `"syst"`).
- `schema_version`: Manifest schema version (default: 1).
- `upstream_artifacts`: Dictionary mapping role names to upstream artifact IDs.
- `params`: Serialized dictionary of operation parameters.
- `files`: Sequence of `FileRecord(name, size_bytes, content_id)`.
- `created_at`: ISO 8601 timestamp string.
- `run`: Optional `RunProfile`.
- `execution`: Optional `ExecutionMetadata`.

### 3.2 Canonical Hasher (`hasher.py`)

- **`canonical_dumps(obj)`**: Serializes Python structures deterministically. Dataclasses preserve their declaration field order; dictionaries have their keys sorted alphabetically; floats are normalized to avoid IEEE precision divergence.
- **`derive_id(operation, params, upstream=None)`**: Derives the unique ID:
  - Operation mappings: `"staging"` $\to$ `"staging"`, `"fit-input"` $\to$ `"input"`, `"fit"` $\to$ `"fit"`, `"toy"` $\to$ `"toy"`, `"syst"` $\to$ `"syst"`.
  - Normalizes `params` and `upstream` into canonical JSON.
  - Computes SHA-256 over `{"operation": operation, "params": params, "upstream": upstream}`.
  - Returns `f"{kind}_{digest[:16]}"`.

---

### 3.3 Manifest I/O & Validation (`manifest.py`)

- **`validate_manifest(data)`**: Validates required keys, checks `schema_version >= 1`, verifies valid `artifact_id` format, and asserts that forbidden label fields do not contaminate `params`.
- **`write_manifest(manifest, path_or_dir)`**: Validates and serializes formatted `manifest.json`.
- **`read_manifest(path_or_dir)`**: Reads, validates, and parses `manifest.json` into a `Manifest` instance.

---

### 3.4 Filesystem ArtifactStore (`store.py`)

The `ArtifactStore` provides the storage interface for managing artifacts on disk.

#### On-Disk Layout
```text
<artifact_store_root>/
  objects/
    staging/
      a1/
        staging_a1b2c3d4e5f67890/
          events.root
          manifest.json
    fit-input/
      f9/
        input_f9e8d7c6b5a43210/
          input.h5
          manifest.json
    fit/
      3c/
        fit_3c4d5e6f7a8b9c0d/
          fit.h5
          fit.nc
          manifest.json
```

#### API Methods
- `store.object_dir(artifact_id, artifact_type=None) -> Path`: Resolves the absolute directory path using the artifact's 2-character hex prefix.
- `store.exists(artifact_id, artifact_type=None) -> bool`: Checks if the directory and its `manifest.json` exist.
- `store.get_path(artifact_id, name, artifact_type=None) -> Path`: Returns the path to an individual file (e.g. `input.h5`, `fit.nc`) for direct opening by PyROOT, HDF5, or ArviZ.
- `store.get_manifest(artifact_id, artifact_type=None) -> Manifest`: Loads and returns the parsed `Manifest`.
- `store.put(artifact_id, files, manifest, artifact_type=None) -> Path`: Atomically publishes files and `manifest.json`.

## 4. Usage Recipes

### Deriving an ID and Publishing an Artifact

```python
import uuid
from datetime import datetime, timezone
from pathlib import Path

from qpym2.storage import (
    ArtifactStore,
    FileRecord,
    InputParams,
    Manifest,
    RunProfile,
    derive_id,
)

# 1. Define physical input parameters
params = InputParams(
    bin_size=2.5,
    esum_min=2400.0,
    esum_max=2570.0,
    threshold=200.0,
    co_cut="gamma10_v150",
    ndbd_cutoff="u1740",
    co_shift=0.8,
)

# 2. Derive deterministic artifact ID with upstream dependency
staging_id = "staging_a1b2c3d4e5f67890"
artifact_id = derive_id("fit-input", params, upstream={"staging": staging_id})
print(f"Derived ID: {artifact_id}")

# 3. Check if artifact is already cached
store = ArtifactStore("/path/to/artifact_store")
if store.exists(artifact_id):
    print("Cache hit! Skipping computation.")
    input_file = store.get_path(artifact_id, "input.h5")
else:
    # 4. Produce output file (e.g., input.h5)
    output_path = Path("/tmp/scratch_input.h5")
    output_path.write_bytes(b"HDF5_PAYLOAD")

    # 5. Assemble manifest
    manifest = Manifest(
        artifact_id=artifact_id,
        artifact_type="fit-input",
        schema_version=1,
        upstream_artifacts={"staging": staging_id},
        params=params.to_dict(),
        files=(FileRecord(name="input.h5", size_bytes=output_path.stat().st_size),),
        created_at=datetime.now(timezone.utc).isoformat(),
        run=RunProfile(sampler="hists_builder"),
    )

    # 6. Publish atomically to the store
    published_dir = store.put(artifact_id, files={"input.h5": output_path}, manifest=manifest)
    print(f"Published to: {published_dir}")
```

### 3.5 Disposable SQLite Catalog (`catalog.py`)

Artifact searches and metadata queries across thousands of objects are accelerated by `<store_root>/catalog.sqlite`. Because SQLite WAL does not guarantee reliable concurrent multi-process writes on networked filesystems (NERSC CFS), SLURM workers publish self-contained `manifest.json` files independently; a single-process indexer populates SQLite on demand.

#### Database Schema
- **`artifacts`**: `artifact_id` (PK), `artifact_type`, `schema_version`, `created_at`, `execution_id`, `hostname`, `git_commit`, `git_dirty`, `slurm_job_id`, `seed`, `legacy`.
- **`params`**: `artifact_id` (PK), indexed scalar columns (`co_cut`, `ndbd_cutoff`, `co_shift`, `ndbd_shift`, `smooth`, `bin_size`, etc.), and raw `json_blob`.
- **`files`**: `artifact_id`, `filename`, `size_bytes`, `content_id`.
- **`upstream`**: `artifact_id`, `upstream_role`, `upstream_id`.

#### CLI Tool: `qpym2-catalog`

```bash
# Index or update catalog from all manifests in store
qpym2-catalog index /path/to/artifact_store

# Drop and rebuild index from scratch
qpym2-catalog index /path/to/artifact_store --rebuild

# Query fits matching parameter cuts
qpym2-catalog query /path/to/artifact_store --type fit --co-cut gamma10_v150 --co-shift 0.8

# Inspect complete manifest JSON by artifact ID
qpym2-catalog info /path/to/artifact_store fit_a1b2c3d4e5f67890
```

### 3.6 Campaign Views & Flat Indices (`views.py`)

To allow scientists to inspect and navigate analysis results without parsing hexadecimal hashes, `qpym2.storage.views` generates organized symlink trees:

```text
<artifact_store_root>/
  views/
    <campaign_name>--<campaign_id>/
      artifacts.tsv                  # Flat inventory of campaign artifacts
      models/
        model_gamma10_v150_u1740/
          input.h5                   -> ../../../objects/fit-input/ab/<id>/input.h5
          nominal_fit/               -> ../../../objects/fit/cd/<id>/
          systematics/co_shift_0p8/  -> ../../../objects/fit/ef/<id>/
```

Generate programmatically via:

```python
from qpym2.storage.store import ArtifactStore
from qpym2.storage.views import build_campaign_view

store = ArtifactStore("/path/to/artifact_store")
view_path = build_campaign_view(store, campaign_name="tech_note", campaign_id="2026-10-17")
print(f"Created campaign view at {view_path}")
```

## 4. Pipeline Runner Integration & Caching Policy

All pipeline runners directly interface with the `ArtifactStore`:

1. **`run_create_staging.py`**:
   - Publishes staged ROOT outputs (`events.root`, `0vbb.root`, `data.root`) under `objects/staging/<prefix>/<staging_id>/`.
2. **`run_create_input.py`**:
   - Computes `input_id` from `InputParams`.
   - Skips generation if `store.exists(input_id)` unless `--force` is provided.
   - Publishes `input.h5` and sidecar manifest.
3. **`run_single_fit.py`**:
   - Derives `fit_id` from `FitParams` and upstream `input_id`.
   - Checks `store.exists(fit_id)`; skips execution immediately on cache hit unless `--force` is passed.
   - Saves `fit.h5` and `fit.nc`, creates `Manifest` with runtime `RunProfile` and `ExecutionMetadata`, and atomically publishes to the store.
4. **`run_toy_batch.py`**:
   - Avoids inode explosion on NERSC by saving consolidated batch summary tables (`results.h5` / `results.parquet`).
   - Publishes batch artifact into `objects/toy/<prefix>/<toy_id>/`.
