# QPyM2 v0.6: Storage Architecture & Configuration Guide

This document describes the modern data management and configuration system in QPyM2 `v0.6.0`, implementing the storage architecture defined in [docs/ai/reviews/2026-10-29-data-storage-review.md](2026-10-29-data-storage-review.md) backed by the `qpym2.storage` package and a structured 4-tier **Hydra Configuration** system.

---

## 1. Architectural Overview

### Layout

```text
staging/<component_name.root>

fit_data/
  roi_2400_2570/thr200/h2uv_b2.5/
    input/
      data.h5
      data_blinded.h5
      <component_name>_<input_UUID>.h5
    output/
      fit_<output_UUID>.h5
      fit_<output_UUID>.nc             # optional: traces retained for selected fits only
  studies/
    <study-name>/
      <study-name>.manifest
      <study-name>.sqlite
      results.csv                      # aggregated summary statistics across study points
      plots/                           # comparative study plots, pulls, systematic scans
```

### Key Design Principles

1. **Path-Encoded Geometry Coordinates**:
   - Directory levels encode geometry and binning: `roi_<min>_<max>/thr<val>/<coord>_b<bin_size>/`.
   - Subdirectories: `input/` and `output/`.
2. **Deterministic UUIDs for Parameter Variations**:
   - `<input_UUID>`: Deterministic 12-char SHA-256 hash of the applied parameter set (staging contract version, cuts, and coordinate transforms). Sources sharing the same parameters share the exact same `<input_UUID>`.
   - `<output_UUID>`: Deterministic 12-char SHA-256 hash of fit-point settings (input template references, component grouping, likelihood, smoothing, priors, MCMC configuration).
3. **Source-Level Template Storage and Parameter Tagging**:
   - Templates stored in `input/` map 1-to-1 with staged ROOT sources (`staging/<component_name>.root` $\rightarrow$ `input/<component_name>_<input_UUID>.h5`, e.g. `208Tl_<base_UUID>.h5`, `60Co_<shift_UUID>.h5`).
   - All invariant sources evaluated under nominal parameters visibly share the common baseline `<input_UUID>`.
   - Parameters affecting only one source (e.g. `co_shift` for `60Co`, or `ndbd_shift` for `ndbd`) produce a distinct `<input_UUID>` only for the shifted parameter variation, while invariant sources (`208Tl`, `238U`, etc.) remain at the baseline `<input_UUID>`.
   - Templates store original, **unsmoothed** histograms. Component grouping into likelihood components and smoothing are applied downstream during fit setup.
4. **Decoupled Study Aggregation**:
   - `fit_data/studies/<study-name>/` houses study records, manifests, and comparative artifacts.
   - Workers write independent outputs; a post-run collection step aggregates results into `results.csv` and indexes them in `<study-name>.sqlite`.

## 2. Configuration System (4 Tiers)

The configuration system uses Hydra and OmegaConf composed programmatically via `qpym2.cfg.hydra_adapter.HydraConfigManager`.

```text
config/
├── config.yaml              # Master entry point (defaults: local, default, base, tech_note)
├── environments/            # Tier 1: System infrastructure & paths
│   ├── base.yaml            # Defaults, directory variables, output_paths.fit_data_dir
│   ├── local.yaml           # Local workstation data root
│   └── nersc.yaml           # NERSC Perlmutter data paths
├── staging/                 # Tier 2: Staging transform contract
│   └── default.yaml         # Preselection cuts & source file match patterns
├── analysis/                # Tier 3: Physics baseline & conventions
│   └── base.yaml            # Baseline background component grouping & standard cuts
└── models/                  # Tier 4: Physics models & ROI
    └── tech_note.yaml       # tech_note_200, tech_note_250, tech_note_150, tech_note_3comp
```

### Loading Configuration in Python

```python
from qpym2.cfg.hydra_adapter import HydraConfigManager
from qpym2.cfg.config_builders import (
    build_staging_config,
    get_fit_data_dir,
    get_model_storage_coords,
)

# Load configuration with environment selection
cfg = HydraConfigManager.get_config(environment="local")

# Resolve storage directories and model coordinates
fit_data_dir = get_fit_data_dir(cfg)
coords = get_model_storage_coords(cfg, model_key="tech_note_200")
# coords -> {'roi': (2400.0, 2570.0), 'threshold': 200.0, 'coord': 'h2uv', 'bin_size': 2.5}
```

## 3. Storage Module Reference (`qpym2.storage`)

The `qpym2.storage` package provides the complete foundation for path routing, parameter hashing, HDF5 metadata, and study indexing.

### 3.1 Path Routing (`paths.py`)

- `get_parameter_dir(fit_data_root, roi, threshold, coord, bin_size) -> Path`: Combines coordinate components into `roi_<min>_<max>/thr<val>/<coord>_b<bin_size>/`.
- `get_input_dir(param_dir) -> Path`: Returns `param_dir / "input"`.
- `get_output_dir(param_dir) -> Path`: Returns `param_dir / "output"`.
- `get_template_path(input_dir, component, input_uuid) -> Path`: Returns `input_dir / f"{component}_{input_uuid}.h5"`.
- `get_data_path(input_dir, blinded=False) -> Path`: Returns `input_dir / "data.h5"` or `"data_blinded.h5"`.
- `get_fit_path(output_dir, output_uuid, ext=".h5") -> Path`: Returns `output_dir / f"fit_{output_uuid}{ext}"`.
- `get_study_dir(fit_data_root, study_name) -> Path`: Returns `fit_data_root / "studies" / study_name`.
- `get_study_paths(study_dir, study_name) -> dict`: Returns paths to manifest, SQLite DB, `results.csv`, and `plots/`.

### 3.2 Schema & Normalization (`schema.py`)

- `normalize_cut_string(cut: str) -> str`: Normalizes whitespace, removes trivial `true` tokens, and standardizes `&&` chains.
- `normalize_float(val: float, precision: int = 6) -> float`: Rounds floats to fixed decimal precision to prevent IEEE-754 serialization discrepancies across systems.
- `build_template_hash_dict(...) -> dict`: Constructs canonical schema dictionary for template parameter sets (`TemplateHashParams`), identifying variations (cuts, transforms, staging contract) independently of the component name.
- `build_fit_hash_dict(...) -> dict`: Constructs canonical schema dictionary for fits (`FitHashParams`).

### 3.3 Deterministic Hasher (`hasher.py`)

- `canonical_json(obj: Any) -> str`: Recursively sorts dictionary keys, formats numbers, and produces whitespace-free JSON strings (`separators=(',', ':')`).
- `hash_dict(data: dict, length: int = 12) -> str`: Computes truncated SHA-256 hex digest.
- `compute_input_uuid(template_params: dict) -> str`: Computes `<input_UUID>` for a parameter variation state.
- `compute_output_uuid(fit_params: dict) -> str`: Computes `<output_UUID>`.

### 3.4 HDF5 Metadata (`metadata.py`)

- `write_hdf5_metadata(fpath, metadata: dict)`: Stores the full parameter dictionary as canonical JSON in `attrs['metadata_json']`, and mirrors top-level primitive attributes.
- `read_hdf5_metadata(fpath) -> dict`: Reads and decodes metadata from HDF5 file-level attributes.

### 3.5 Storage Backend (`backend.py`)

- `write_template(path, hist, edges=None, metadata=None, overwrite=False)`: Writes composite template to HDF5.
- `read_template(path) -> (hist, edges, metadata)`: Reads template array, bin edges, and metadata.
- `write_observed_data(path, data, edges=None, metadata=None, overwrite=False)`: Writes `data.h5` or `data_blinded.h5`.
- `read_observed_data(path) -> (data, edges, metadata)`: Reads observed data.
- `write_fit(path_prefix, table, trace=None, data=None, metadata=None, save_trace=False)`: Writes `fit_<output_UUID>.h5` and optionally `fit_<output_UUID>.nc` (via ArviZ).
- `read_fit(path_prefix) -> (table, trace, data, metadata)`: Reads fit results.
- `template_exists(...)`, `data_exists(...)`, `fit_exists(...)`: Fast cache existence checkers.

### 3.6 Study Management (`study.py`)

- `init_study_db(sqlite_path) -> Path`: Initializes the `study_points` SQLite table.
- `record_study_point(sqlite_path, point_dict)`: Inserts or updates point records.
- `write_study_manifest(manifest_path, manifest_data)` / `read_study_manifest(...)`: Manages `<study_name>.manifest` JSON file.
- `collect_study_results(study_dir, study_name, result_csv_paths=None) -> pd.DataFrame`: Validates and merges worker task CSVs into `results.csv` and marks point records completed in SQLite.

### 3.7 Input Generation (`inputs.py`)

- `resolve_storage_coords(cfg, model_key=None) -> (coords, h2uv_model, param_dir, input_dir)`: Resolves coordinate hierarchy and path routes.
- `build_shift_defs(shift_val, shift_type='ushiftp') -> list[tuple]`: Builds RDataFrame branch definitions for coordinate shifts.
- `generate_source_template(...) -> (path, uuid, is_cached)`: Reads unsmoothed histogram, checks cache, and writes `<component_name>_<input_UUID>.h5`.
- `generate_observed_data(...) -> (path, is_cached)`: Reads event list or binned data, checks cache, and writes `data.h5` / `data_blinded.h5`.
- `create_storage_inputs_for_point(...) -> dict`: Discovers background MC sources, signal, and data, producing all inputs for a parameter point with caching and dry-run preview. Precomputes parameter-level UUIDs (`uuid_base`, `uuid_co`, `uuid_ndbd`).

### 3.8 Studies Module (`qpym2.studies`)

- `load_study_config(study_dir_or_name, overrides=None) -> (cfg, study_dir)`: Loads study directory configuration (`study.yaml`), resolves defaults from Hydra 4-tier base, and deep-merges study-level overrides via OmegaConf.
- `resolve_study_dir(study_dir_or_name) -> Path`: Resolves direct path or registered study names across `studies/`, `config/studies/`, and `fit_data/studies/`.
- `expand_study_points(reference, sweep, default_model_key) -> list[StudyPoint]`: Expands parameter sweeps (Cartesian products) into discrete evaluation points with deterministic IDs.
- `assemble_study(study_dir_or_name, overrides=None) -> Study`: High-level entry point that loads config, expands points, and returns an initialized `Study` instance.
- `Study`: Central coordinator managing parameter points:
  - `check_inputs() -> pd.DataFrame`: Checks existence of all required source templates and observed data in `fit_data/.../input/`, reporting per-point readiness (`READY` vs `MISSING_INPUTS`).
  - `get_missing_inputs() -> dict`: Returns mapping of `point_id` to missing file paths.
  - `print_input_status()`: Formats and prints human-readable ASCII readiness summary table.
  - `generate_inputs(overwrite=False) -> dict`: On-demand materialization of missing inputs using an in-memory histogram cache across points.
  - `check_fits() -> pd.DataFrame`: Checks existence of completed fit HDF5 and NetCDF outputs across study points (`FITTED` vs `PENDING_FIT`).
  - `print_fit_status()`: Formats and prints human-readable fit status table.
  - `run_fits(save_trace=False, force=False)`: Coordinates MCMC Bayesian fits across all study points, skipping completed ones unless `force=True`.
  - `collect_results() -> pd.DataFrame`: Aggregates posterior metrics across completed points into `results.csv` and updates the SQLite index.
  - `to_manifest()` / `save_manifest(path=None)`: Serializes study specifications and required artifacts to `<study_name>.manifest` JSON.

### Python Template Generation and Hashing

```python
from qpym2.storage import (
    build_template_hash_dict,
    compute_input_uuid,
    get_parameter_dir,
    get_input_dir,
    get_template_path,
    write_template,
)

# 1. Build canonical parameter dictionary and compute parameter-set UUID
# (All sources sharing the same staging, cuts, and transforms share this UUID tag)
tpl_params = build_template_hash_dict(
    staging_id="v5.1",
    cuts={"common": "v>150"},
    transforms={"shift_type": "ushiftp", "shift_val": 0.8},
    norm="mode",
)
input_uuid = compute_input_uuid(tpl_params)

# 2. Resolve destination path and persist
param_dir = get_parameter_dir("/data/fit_data", (2400, 2570), 200, "h2uv", 2.5)
inp_dir = get_input_dir(param_dir)
tpl_path = get_template_path(inp_dir, "60Co", input_uuid)

write_template(tpl_path, hist_array, edges=bin_edges, metadata=tpl_params)
```

### Fit Registration and Trace Retention

```python
from qpym2.storage import (
    build_fit_hash_dict,
    compute_output_uuid,
    get_output_dir,
    get_fit_path,
    write_fit,
)

# 1. Build fit parameter dictionary referencing input UUIDs
# (Invariant sources share base_uuid, while 60Co references co_uuid)
fit_params = build_fit_hash_dict(
    model_name="m2",
    data_source="data",
    templates={
        "co60": co_uuid,
        "u238": base_uuid,
        "th232": base_uuid,
        "others": base_uuid,
        "ndbd": base_uuid,
    },
    smoothing={"enabled": True, "method": "smooth_nph2"},
    priors={"sigma_scale": 1.0, "use_sample_std": False},
    roi_settings={"skip_roi": None},
    mcmc={"chains": 8, "draws": 20000},
)
output_uuid = compute_output_uuid(fit_params)

# 2. Persist fit summary and optional trace
out_dir = get_output_dir(param_dir)
fit_prefix = out_dir / f"fit_{output_uuid}"

write_fit(
    fit_prefix,
    table=fit_components_df,
    trace=posterior_trace,
    data=data_events,
    metadata=fit_params,
    save_trace=True,  # Persists .nc only when requested
)
```


### Signal-Injection Bias Studies

Bias studies evaluate estimator linearity and coverage under varying signal injection levels $N_{\text{inj}}$. Rather than treating $N_{\text{inj}}$ as a discrete sweep axis in `study.yaml`, a study defines physical coordinate sweeps (e.g., `co_shift`), with bias settings configured under a `bias:` block:

```yaml
name: example_bias_study
description: "Example Co-60 shift study with signal injection bias toys"
model_key: tech_note_200

sweep:
  co_shift: [0.0, 0.8, 1.0, 1.2]

bias:
  n_toys: 200
  bias_min: 5.0
  bias_max: 200.0
  xmin: 15.0
```

For each study point:
1. **Pseudo-data Sampling**: Templates and edges are retrieved from storage (`setup_storage_fit`). For each toy, $N_{\text{inj}} \sim \text{Uniform}(\text{bias\_min}, \text{bias\_max})$ is drawn, and pseudo-data is sampled via `sample_hist(get_sum_hist(fit_comps, norms))`.
2. **Fit Execution**: The pseudo-data is fit using PyMC (`m2.make_fik` and `m2.m2_model`).
3. **Pull & Posterior Statistics**: Posterior mode, 34% upper error (`upp34 - mode`), and pull:
   $$\text{pull} = \frac{\hat{N} - N_{\text{inj}}}{\text{upp34} - \hat{N}}$$
   are recorded per toy in `<study_dir>/tasks/toys_bias_<point_id>.csv`.
4. **Calibration Fit**: `collect_bias_results()` merges the tasks into `results.csv`, unflattens column names via `_unflatten_columns`, and fits the linear calibration line $y = a \cdot x + b$ for $N_{\text{inj}} > x_{\text{min}}$ via `get_bias_from_fitdf`, writing calibration parameters to `<study_dir>/bias_calibration.json` and updating `<study_name>.sqlite`.


### Expected Sensitivity Studies

Sensitivity studies quantify expected discovery and exclusion potential under the background-only ($H_0$) hypothesis ($N_{0\nu} = 0$). Settings are configured under a `sens:` block in `study.yaml`:

```yaml
name: example_sens_study
description: "Expected 90% CL sensitivity study for tech_note_200 across Co-60 shifts"
model_key: tech_note_200

sweep:
  co_shift: [0.0, 0.8, 1.0, 1.2]

sens:
  n_toys: 200
  seed: 42
  chains: 4
  draws: 2000
  tune: 500
  bias_calibration: "studies/example_bias_study/bias_calibration.json"
```

For each study point:
1. **$H_0$ Pseudo-Data Generation**: Signal normalization is set to zero (`norms[isig] = 0.0`) while background components remain at baseline rates. Poisson-fluctuated datasets are generated via `sample_hist(hsum, xedges, yedges)`.
2. **Fit Execution & Posterior Stats**: Fits are executed with PyMC. Each toy records `ndbd_p90` (Bayesian 90% C.L. upper limit), `ndbd_mode`, `ndbd_upp34`, `ndbd_p16`, `logp_mode_`, and background parameters into `<study_dir>/tasks/toys_sens_<point_id>.csv`.
3. **Aggregation & Containment Bands**: `collect_sens_results()` aggregates task CSVs into `results.csv`, extracts the median expected sensitivity (`median(ndbd_p90)`), $\pm 1\sigma$ interval ($[p_{16}, p_{84}]$), and $\pm 2\sigma$ interval ($[p_{02.5}, p_{97.5}]$), exports `sens_summary.json`, and records points in `<study_name>.sqlite`.
4. **Bias Correction & Physics Conversion**: When `bias_calibration` is provided, upper limits are bias-corrected via $N_{\text{bc}} = \max(0, (N_{90} - b)/a)$ to yield unbiased sensitivity intervals and conversion to half-life bounds $T_{1/2}^{0\nu} = \ln(2) / \Gamma_{90}$.


### Interactive Marimo Notebooks

Interactive inspection and generation workbenches live under `notebooks/marimo/`:

```bash
# Launch the staging inventory workbench
marimo edit notebooks/marimo/staging_inventory.py

# Launch the storage input generation and inspection workbench
marimo edit notebooks/marimo/input_creation.py

# Launch the fit execution, posterior diagnostics, and results workbench
marimo edit notebooks/marimo/fit_run_results.py

# Launch the signal injection bias & calibration workbench
marimo edit notebooks/marimo/bias_study_workbench.py

# Launch the expected sensitivity & containment workbench
marimo edit notebooks/marimo/sens_study_workbench.py
```

- **`staging_inventory.py`**: Explores the 4-tier configuration, verifies data root paths, inspects staged ROOT files, checks event counts, and cross-references JAGS background model components.
- **`input_creation.py`**: Interactively previews deterministic UUID hashes, checks cache hit/miss status across parameter variations (Co-60 cuts/shifts, NDBD cutoffs/shifts), triggers template generation, explores embedded HDF5 metadata (`attrs['metadata_json']`), and plots 2D distributions and 1D projections.
- **`fit_run_results.py`**: Interactively configures and executes Bayesian MCMC fits against the storage layout, previews deterministic `<output_UUID>`s, inspects posterior summaries and trace convergence, plots 2D data-vs-fit and 1D projections, and checks study sweep status and parameter scans.
- **`bias_study_workbench.py`**: Interactively analyzes signal-injection linearity, parameter stability ($a, b$ vs shift), raw vs bias-corrected posterior samples, and posterior marginalization.
- **`sens_study_workbench.py`**: Interactively inspects sensitivity distributions (`ndbd_p90`), median limits with $\pm 1\sigma / \pm 2\sigma$ containment bands across systematic sweeps, optional bias-corrected limits, and comparison with observed data fits.
